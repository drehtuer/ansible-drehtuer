== Overview

:url-drehtuer-de: https://drehtuer.de[drehtuer.de^]
:url-drehtuer-net: https://drehtuer.net[drehtuer.net^]
:url-ansible: https://www.ansible.com[Ansible^]
:url-dev-container: https://containers.dev[Development Container^]
:url-vscode: https://code.visualstudio.com[Visual Studio Code^]
:url-invoke: https://docs.pyinvoke.org/en/stable[python-invoke^]

This repo contains the configuration for the hosts link:{url-drehtuer-de}/link:{url-drehtuer-net} as link:{url-ansible} scripts.
The environment is provided as configuration for link:{url-dev-container} and link:{url-vscode}.

The goal is a complete, documentation-as-code setup of the server so that it can be rebuilt or migrated to another host with minimal manual effort. The server runs nginx (serving Nextcloud, with Let's Encrypt certificates), Postfix + Dovecot (with RSpamd for anti-spam filtering, including learning from user feedback), SSH, MariaDB + Redis, and two DNS servers side by side — Unbound resolving recursively on loopback, and NSD answering authoritatively on the public addresses as a hidden primary for `drehtuer.net` — plus supporting system services (firewall, fail2ban, cron, NTP, Docker).

Secrets (passwords, private keys, personal data) are never stored unencrypted in this repository — they are encrypted with `ansible-vault`. The vault password itself is kept in `vault/secret.txt`, which is excluded from version control and must never be committed.

Playbooks are run through `tasks.py` (link:{url-invoke}) rather than calling `ansible-playbook` directly, e.g.:

[source, bash]
----
invoke run-playbook --playbook=playbooks/http.yml
----

See `invoke --list` for all available tasks.

== Linting

:url-yamllint: https://yamllint.readthedocs.io/en/stable[yamllint^]
:url-ansible-lint: https://ansible.readthedocs.io/projects/lint[ansible-lint^]
:url-ruff: https://docs.astral.sh/ruff[ruff^]
:url-asciidoctor: https://asciidoctor.org[asciidoctor^]

YAML is checked with link:{url-yamllint} (style, configured in `.yamllint`) and link:{url-ansible-lint} (Ansible practices, configured in `.ansible-lint`, strictest `production` profile).
Python is checked and formatted with link:{url-ruff} (configured in `pyproject.toml`).
The AsciiDoc pages are checked with link:{url-asciidoctor} itself, run as `--failure-level=WARN` so that a dropped table cell, a missing include or a skipped section level fails instead of scrolling past — it needs no configuration file. Note it does *not* check cross-references: an unresolved one renders as a dead link and is reported nowhere.
All four are installed in the Dev Container.

[source, bash]
----
# Everything
invoke lint
# Apply the fixes the linters can make themselves
invoke lint --fix
# Or one at a time
invoke lint-yaml
invoke lint-ansible
invoke lint-python
invoke lint-docs
----

The same checks run automatically in two places:

* *Before each commit*, via the hook in `.githooks/pre-commit`, which lints the staged YAML and Python files — the AsciiDoc check is deliberately not in the hook yet, so it runs only via `invoke lint` and in CI. Git only picks the hook up once per clone:
+
[source, bash]
----
invoke install-hooks
----
+
Use `git commit --no-verify` to bypass it for a single commit.
* *On every push to `main` and every pull request*, via `.github/workflows/lint.yml`.

Editor-side formatting is described in `.editorconfig`, which mirrors the same rules (two spaces, 80 columns, final newline, no trailing whitespace). VS Code needs the EditorConfig extension for it to take effect; it is installed by the Dev Container.

== Documentation

:url-pages: https://pages.github.com[GitHub Pages^]
:url-skill-testlab: .claude/skills/testlab/SKILL.md[testlab^]
:url-skill-run-ansible: .claude/skills/run-ansible/SKILL.md[run-ansible^]

:url-antora: https://antora.org[Antora^]

Every page under `doc/` is AsciiDoc and renders to a static site with link:{url-antora}:

[source, bash]
----
invoke docs      # -> public/
----

Antora wants its pages under `modules/<name>/pages/`. Moving `doc/` there would invalidate the 179 references to `doc/*.adoc` spread across 86 files - role comments, playbooks, inventory, `tasks.py` - so the build assembles that layout under `build/` from the sources instead, and the repository keeps its own vocabulary. What it costs is Antora's *Edit this Page* link, which cannot be mapped back: `index.adoc` came from `README.adoc` and the skill pages from Markdown two directories away.

The two `.claude/skills/*/SKILL.md` files are converted by `kramdoc` on the way in, since Antora reads AsciiDoc and nothing else. They are included because the AsciiDoc pages lean on them - `doc/TESTING.adoc` alone points at `.claude/skills` ten times:

* link:{url-skill-testlab} - the disposable hosts a role is proven on before production sees it.
* link:{url-skill-run-ansible} - how this repository is linted and tested.

One file of Antora's default UI is overridden in `docs-ui/`, dropping the demo navbar it ships - Products, Services and a Download button, all placeholders. The published site references no third party: Antora copies its UI's CSS and JavaScript into the output. Fetching that UI bundle is the build's one network dependency.

`.github/workflows/docs.yml` publishes it to link:{url-pages} on every push to `main`.

== Testing

:url-doc-testing: doc/TESTING.adoc[Testing]

Beyond linting there are static tests (argument specs and template rendering, no host involved), molecule scenarios that converge a role in a container and check it is idempotent, and a drift check against the real host.

[source, bash]
----
# Static tests only: quick, no container needed
invoke test-static
# Molecule scenarios, needs Docker
invoke test-molecule
# Both
invoke test
# What differs between this repo and the real host?
# Local only: needs the vault password.
invoke check-drift
----

See link:{url-doc-testing} for what each layer catches, what it does not, and how to add a scenario for another role.

== Backup

:url-doc-backup: doc/BACKUP.adoc[Backup]

`roles/backup` takes a nightly `restic` snapshot of the state a playbook run cannot produce - the database dumps, the home directories and mail, the secrets generated on the host that this repository does not hold - and verifies the repository weekly. It reports its own outcome to Prometheus, so a backup that stops running is visible rather than merely absent.

[source, bash]
----
# Deploy it
invoke run-playbook --playbook=playbooks/backup.yml --hosts=production
# Run one now, rather than waiting for the timer
ssh <host> sudo systemctl start backup.service
----

See link:{url-doc-backup} for what is backed up, what deliberately is not and why, and - the part most likely to cost time under pressure - the order a restore has to happen in.
